# Expire Transcript narration and detail in place

Narration and detail in a Workspace's Transcript are retained for 30 days from each entry's append time. The window is fixed across Organizations for `0.3`. Shared-state entries never expire. This gives the live view and the five-day acceptance run room to work while bounding the content generated by long Sessions.

An hourly, bounded sweep replaces due narration and detail content with a permanent tombstone at the same sequence position, even in a sealed Workspace. The tombstone retains the original kind, sequence, append time and expiry time, but no content or payload reference. This records the expiry inside the Transcript without creating a new entry in a sealed Workspace or invalidating a cursor that points at the old position. A read requesting that kind shows the tombstone; a shared-state-only read skips it. The sweep removes referenced payload content in the same transaction. Retention expiry is separate from deliberate deletion, which remains a `0.4` concern.

An individual payload over 64 KiB is represented by a reference in its Transcript entry. For the SQLite store, the content lives in a separate payload table and is written atomically with the entry; a reference to shared-state content lasts as long as that entry. Keeping the reference distinct from the content allows the `0.7` store change without changing the Transcript's entry shape. Files beside the database were rejected because an entry and its content could disagree after a crash.
