# 0.4 build graph and final acceptance

The final planning task, [Specify the final 0.4 acceptance gate and reconcile the build graph](https://github.com/openkestrel/kestrel/issues/637), reconciled the chosen operator and contributor tracks before publishing [0.4/79 — Accept the tagged one-command release from both Clients](https://github.com/openkestrel/kestrel/issues/646). This is a planning audit, not evidence of implemented behavior or release acceptance.

## Dependency audit

The planning snapshot contained all 78 numbered build owners exactly once and 297 native prerequisite edges. Every explicitly listed body blocker had a native edge; generated-leaf prerequisites added during wire coordination were present. No cycles or concrete missing producer prerequisite were found. Open numbered owners carried milestone 0.4, ready-for-agent and exactly one approved difficulty.

The final gate has 23 direct native prerequisites: 19 terminal numbered owners whose prerequisite closure covers all 78 builds, the previous acceptance gate and three completed App/accessibility foundations. This stays below GitHub's 50 blocked-by limit. The gate also checks all chosen owners are complete because closing a terminal issue does not enforce completion of its prerequisites. Native edges remain the live authority; this document records the planning audit.

Feature owners author and generate their new schemas. Response migration families consume the generated leaf and existing surfaces; they do not introduce reverse dependencies from feature producers to final wire contraction. Candidate preparation and promotion-interface implementation never wait on the acceptance execution they enable.

## Ownership reconciliation

The first-run, workbench, refusal, contributor and wire specs remain indexes and contract owners. Grouped polish findings retain their existing index rather than duplicate implementations. The workbench spec now links its eleven native children and the first browser Session consumes shared queue recovery. The existing CLI sign-in owner explicitly updates the manual subscription-profile guide.

The original App foundations and moderate accessibility fix are reused. Contributor measurements remain with [0.4/35 — Write one-page CONTRIBUTING and validate the contributor slice](https://github.com/openkestrel/kestrel/issues/595). The accepted 0.3 record reports success, but [Run the 0.3 joinable-work acceptance gate](https://github.com/openkestrel/kestrel/issues/426) remains a native prerequisite until tracker closure; prose does not bypass it.

The maintainer approved deferring [Know a fork's pull request availability before its first pull request arrives](https://github.com/openkestrel/kestrel/issues/444) to 0.7. It had no allocated owner in this map and is not required for the selected single-repository first-run journeys. ROADMAP records the scope boundary; the question remains open at its new rung.
